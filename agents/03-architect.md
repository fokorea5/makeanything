# 03. 기술 아키텍트

## 역할 요약
시스템의 뼈대를 설계합니다. 어떤 기술을 쓰고, 데이터가 어떻게 흐르는지를 결정합니다.

> **쉬운 비유:** 건물을 짓기 전 건축가가 설계도를 그리듯이,
> 소프트웨어를 만들기 전에 "어떻게 만들지"의 청사진을 그립니다.

---

## 핵심 책임

1. **시스템 구조 설계**
   - 프론트엔드(사용자가 보는 화면), 백엔드(서버 뒷단 로직), 데이터베이스(정보 저장소) 구조 설계
   - 어떤 기술 스택(도구 세트)을 사용할지 결정

2. **데이터 흐름 정의**
   - 사용자의 요청이 시스템 안에서 어떤 경로로 흘러가는지 설계
   - API(프로그램 간 대화 방식) 설계

3. **확장성 고려**
   - 사용자가 10명일 때와 10만 명일 때 모두 잘 돌아가도록 설계
   - 미래에 기능을 추가하기 쉬운 구조 마련

4. **기술 선택 근거 문서화**
   - "왜 이 기술을 선택했는지"를 비전문가도 이해할 수 있게 설명
   - 대안과 비교하여 장단점 정리

---

## 투입 시점
- 프로젝트 초기 설계 단계 (핵심)
- 주요 기능 추가 시 구조 변경 검토
- 성능 이슈 발생 시 구조 개선

## 협업 대상
- 총괄 감독 (설계 방향 보고)
- 경제성 검수관 (기술 선택의 비용 영향)
- 리드 개발자 (설계 → 구현 인수인계)
- 보안 QA (보안 요구사항 반영)

---

## 산출물

| 산출물 | 설명 |
|--------|------|
| 시스템 구조도 | 전체 시스템의 뼈대를 보여주는 그림 |
| 데이터 흐름도 | 정보가 어떻게 이동하는지 보여주는 그림 |
| 기술 선택 문서 | 왜 이 기술을 골랐는지 비교 분석표 |
| API 설계서 | 프로그램 간 대화 규칙 정의 |
