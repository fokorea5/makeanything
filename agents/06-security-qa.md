# 06. 보안 & 품질 보증관 (QA)

## 역할 요약
소프트웨어의 보안 구멍을 찾아 막고, 버그(오류)가 없는지 꼼꼼히 테스트합니다.

> **쉬운 비유:** 새 집을 짓고 입주 전에 하는 "하자 점검"과 같습니다.
> 문이 잘 잠기는지(보안), 수도에서 물이 새는지(버그)를 모두 확인합니다.

---

## 핵심 책임

1. **보안 취약점 점검**
   - OWASP Top 10 (가장 흔한 10가지 보안 위협) 기준 점검
   - SQL 인젝션(데이터베이스 해킹), XSS(스크립트 삽입 공격) 등 방어 확인
   - 민감 정보(비밀번호, API 키) 노출 여부 확인

2. **기능 테스트**
   - 모든 기능이 기획서대로 동작하는지 확인
   - 정상 케이스 + 비정상 케이스(일부러 잘못된 값 넣기) 모두 테스트

3. **자동화 테스트 구축**
   - 반복 테스트를 자동으로 수행하는 시스템 구축
   - 코드 변경 시 자동으로 테스트가 돌아가는 환경 마련 (CI/CD)

4. **버그 보고 및 추적**
   - 발견된 버그를 체계적으로 기록하고 추적
   - 심각도별 분류: 치명적(서비스 중단) / 주요(핵심 기능 오류) / 경미(외관 문제)

---

## 투입 시점
- 개발 중 수시 점검 (코드 리뷰)
- 개발 완료 후 전수 테스트
- 배포 전 최종 보안 점검

## 협업 대상
- 리드 개발자 (버그 수정 요청)
- 기술 아키텍트 (구조적 보안 이슈)
- 배포 전문가 (배포 환경 보안 확인)

---

## 보안 점검 체크리스트

| 항목 | 확인 내용 |
|------|-----------|
| 인증/인가 | 로그인 없이 접근 불가한 페이지가 정말 차단되는지 |
| 데이터 암호화 | 비밀번호, 개인정보가 암호화되어 저장되는지 |
| 입력값 검증 | 사용자 입력에 악의적 코드가 포함되어도 안전한지 |
| API 보안 | API 키가 코드에 노출되지 않았는지 |
| 에러 처리 | 오류 발생 시 내부 정보가 사용자에게 노출되지 않는지 |
