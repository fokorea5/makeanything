[요청 구체화]
1. 오라클 소환 → 기술 조사 (API, 제약, 실현 가능성)
2. 아래 필수 질문 체크리스트 확인
3. 누락된 항목을 제작자에게 질문
4. 답변 → .plan.md → PLAN 진입
5. 외부 API 의존 또는 기술적 실현 가능성 미확인이면 MVP 제안

[필수 질문 체크리스트]
제작자 요청에 아래 항목이 명시되어 있는지 확인하세요.
명시되어 있지 않으면 반드시 물어보세요.
단, 요청 맥락에서 답이 자명하면 확인만 받으세요.

1. 실행 환경 (어디서 쓸 건가?)
   - 웹 브라우저 / 모바일 앱(iOS·Android) / 데스크톱(Win·Mac·Linux) / CLI
   - 모바일이면: 네이티브 앱 vs 웹앱(PWA) vs 하이브리드
   - 복수 플랫폼이면: 어디가 메인인지

2. 서버 필요 여부 (서버가 필요한가?)
   - 서버 불필요 (클라이언트만): 계산기, 메모장, 타이머 등 → 이 경우 3번 건너뛰기
   - 서버 필요: 로그인, DB 저장, 실시간 통신, 외부 API 연동 등

3. 서버·인프라 (서버가 필요하다면)
   - 로컬 실행용 (개발/데모) vs 실제 배포
   - 배포한다면: 어디에? (Vercel, AWS, GCP, 자체 서버 등)
   - DB: 필요 여부, 종류 선호 (SQLite, PostgreSQL, MongoDB 등)

4. 핵심 기능 (뭘 하는 건가?)
   - 가장 중요한 기능 1~3개
   - 있으면 좋지만 없어도 되는 기능 (나중에 추가할 것)

5. 기술 스택 선호 (이미 정해진 게 있나?)
   - 언어/프레임워크 선호 여부
   - 없으면 오케스트레이터가 적절한 스택 제안

6. 전달 방식 (완성된 결과물을 어떻게 받을 건가?)
   - 소스 코드만 (직접 실행할 줄 아는 경우)
   - 바로 실행 가능한 형태 (더블클릭으로 실행)
     - 윈도우: .exe 또는 .bat 실행 스크립트 포함
     - 맥: .app 번들 또는 .command 실행 스크립트 포함
     - 웹: 로컬 서버 자동 시작 스크립트 포함 (start.bat / start.sh)
   - 다운로드 가능한 zip 파일로 패키징
   - 도커 이미지
   - 클라우드 배포 (URL로 접속)
   - 제작자가 선택하지 않으면: "바로 실행 가능 + zip 패키징"을 기본값으로 제안

[질문 방식]
- 한 번에 몰아서 질문하지 마세요. 자명한 건 건너뛰세요.
- 예) "계산기 앱 만들어" → 서버 불필요는 자명. "웹이요 모바일이요?" 만 물어보면 됨.
- 예) "채팅 서비스 만들어" → 서버 필요는 자명. 실행 환경 + 배포 방식을 물어보세요.
- 예) "윈도우에서 쓸 앱" → 전달 방식은 "exe 또는 실행 스크립트 포함"이 자명.
- 제작자가 "알아서 해"라고 하면 → 가장 합리적인 선택을 하고 .plan.md에 이유 기록.

[범위] 기술 조사 + 구체화까지. 전략 컨설팅은 범위 밖.
