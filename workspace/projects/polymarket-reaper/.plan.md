## 사용자 원문

> Polymarket Reaper Bot v1.1 (6전략 메타 봇 + 자산 배분)
> 승률 51% 이상의 엣지(Edge)를 만들어낼 6가지 전략:
> 1. 모호성 스코어링 (주관적 키워드/소스 부재 분석)
> 2. 오라클 공포 프리미엄 (분쟁 이력 시장 타겟팅)
> 3. 군중 반대 지표 (Z-score > 2, 주말 드리프트 감지)
> 4. 연관 시장 비효율 (논리적 불일치 조건 + Complete Set)
> 5. 유동성 진공 사냥 (Spread & Depth 비율)
> 6. 메타 봇 스코어링 (위 시그널 중첩 시 가중치 부여)
>
> 베팅 룰: Fractional Kelly 0.4 / 단일 15% / 전체 60% / 일일 손실 8% 서킷
> 유지비용 고려 / 거래빈도 조절 기능 필수
> 실행 비용 최소화
>
> 병목 돌파: Complete Set(속도전/시장가)과 메타 스코어링(분석전/지정가) 충돌 해결
> 알파 증폭: 52~55% 승률을 위한 파생 지표 추가 제안
> 거래빈도 조절 기능

## 승인된 아키텍처: 듀얼 리액터

### Reactor α (Slow Brain) — 3단계 퍼널
- Stage 1 (5분): Ambiguity + Oracle Fear + Market Age★ → Target List (~50개)
- Stage 2 (60초): Contrarian + Correlated + Crowding★ → Hit List (~10개)
- Stage 3 (실시간 WS): Liquidity Vacuum + Vol-Price Divergence★ → Patient Executor

### Reactor Ω (Fast Brain) — 즉시 실행
- Complete Set Arbitrage (WebSocket 실시간) → Sniper Executor (FOK)

### Meta Brain — Golden Cross
- α Hit List + Ω 이상 감지 = Golden Cross → Kelly 1.5x 증폭

### Frequency Governor — 거래빈도 조절기
- TURBO / NORMAL / STEALTH / AUTO (Drawdown 기반 자동 전환)

### Risk Sentinel — 5층 방어
- Kelly 0.4 → 단일 15% → 총 60% → 서킷 8% → DD 감속

## AC (Acceptance Criteria)

### 인프라
- AC-01: asyncio 기반 메인 루프. Reactor α + Reactor Ω가 동시 실행.
- AC-02: py-clob-client를 run_in_executor로 async 래핑. 주문 실행만 SDK 사용.
- AC-03: aiohttp로 Gamma/Data API 네이티브 async 호출.
- AC-04: WebSocket 매니저: market 채널 구독, 자동 재연결(지수 백오프).
- AC-05: config.py에서 모든 설정을 환경변수(.env)로 관리. DRY_RUN=true 기본값.
- AC-06: aiosqlite DB: signals, trades, portfolio, daily_stats 4개 테이블.

### Reactor α (Slow Brain)
- AC-07: Stage 1 — Ambiguity Scoring: 질문/설명에서 모호 키워드 TF-IDF 스코어링 + resolution source 미명시 감지(+0.2). 모호성 > 0.6이면 NO 매수 시그널. 키워드 사전은 config.py 리스트로 관리.
- AC-08: Stage 1 — Oracle Fear Premium: 분쟁 키워드 + YES 할인(>5센트) 감지 → YES 매수 시그널.
- AC-09: Stage 1 — Market Age Freshness★: 생성 48시간 이내 마켓에 가중치 +0.15.
- AC-10: Stage 1 결과 → Target List (구조적 이상이 있는 마켓 목록). 캐시에 저장.
- AC-11: Stage 2 — Contrarian Z-score + 주말 드리프트: 가격 히스토리 Z-score 계산(|Z| > 2.0이면 반대 포지션). 추가로 금~일 가격 변동이 평일 stdev의 2배 초과 시 주말 과잉반응으로 판단, confidence +0.10.
- AC-12: Stage 2 — Correlated Markets: (a) implied conditional = P(A∩B) vs P(A)*P(B), 비율 > 1.5이면 미스프라이싱. (b) 같은 event_id 마켓 가격 합 이상 감지 시 Hit List에 추가 (임계값: 합 > 1.02 또는 < 0.98). 단, AC-12는 분석/식별만 수행. 즉시 실행은 Reactor Ω(AC-18)가 담당.
- AC-13: Stage 2 — Position Crowding Index★: Data API /holders 엔드포인트로 보유자 쏠림 80%+ → Contrarian confidence +0.10. API 미존재 시 이 보조지표 비활성화(graceful degradation).
- AC-14: Stage 2 결과 → Hit List (엣지 확인된 마켓). WebSocket 구독 대상.
- AC-15: Stage 3 — Liquidity Vacuum: Hit List 마켓의 WS 오더북 이벤트 모니터링. spread > 0.05 또는 depth 비대칭 > 3:1.
- AC-16: Stage 3 — Volume-Price Divergence★: WS 체결 이벤트에서 60초간 거래량 합 > 이전 60초의 3배인데 가격 변동 < 0.02이면 "흡수 괴리", 거래량 < 평균의 0.3배인데 가격 변동 > 0.05이면 "진공 괴리" 감지.
- AC-17: Stage 3 통과 시그널 → Patient Executor (GTC/postOnly).

### Reactor Ω (Fast Brain)
- AC-18: Complete Set 실시간 탐지: WS로 같은 event_id 마켓들의 가격 합 모니터링. 합 > 1.03 또는 < 0.97이면 차익 기회.
- AC-19: 차익 기회 발견 → Sniper Executor (FOK) 즉시 실행.

### Meta Brain
- AC-20: Signal 버퍼: market_id별 최근 시그널 수집 (600초 윈도우).
- AC-21: α Hit List 마켓에서 Ω도 이상 감지 = Golden Cross → confidence 보너스 + Kelly 1.5x.
- AC-22: 전략별 가중치 적용 후 가중 평균 confidence 산출.

### 중복 방지 + 유지비용
- AC-39: 동일 마켓 중복 주문 방지: 마켓에 미체결 GTC가 있으면 새 시그널 스킵. 기존 포지션이 있으면 같은 방향 시그널은 스킵, 반대 방향은 기존 포지션 청산 후 신규 진입.
- AC-40: Reactor Ω가 FOK 실행 시, 해당 마켓의 Reactor α 시그널 큐를 소거(Ω 우선).
- AC-41: 유지비용 반영: Kelly Sizer에서 포지션 유지 기간(결제일까지 일수)을 기회비용으로 차감. adjusted_edge = edge - (days_to_settlement / 365 * risk_free_rate). risk_free_rate = 0.05(연 5%, config에서 관리).
- AC-42: 실행 비용 필터: 기대이익(size × edge) - 수수료(fee_rate_bps × size) > 최소 수익 임계값(기본 $0.50). 미만이면 실행 스킵.

### Risk Sentinel
- AC-23: Layer 1 Kelly Sizer: confidence + odds → Fractional Kelly 0.4 × Frequency Governor 배수(TURBO: ×1.0, NORMAL: ×0.7, STEALTH: ×0.4).
- AC-24: Layer 2 Single Market: 단일 마켓 <= bankroll × 0.15.
- AC-25: Layer 3 Total Exposure: 전체 <= bankroll × 0.60.
- AC-26: Layer 4 Circuit Breaker: 일일 손실 >= bankroll × 0.08 → 당일 거래 전면 중단 + 기존 GTC 취소.
- AC-27: Layer 5 Drawdown Throttle: DD >5% ×0.5, >10% ×0.25, >15% 중단. (참고: Frequency Governor의 DD 임계값과 독립 작동. Governor는 스캔 빈도를, Sentinel은 포지션 크기를 조절. 두 효과는 곱셈으로 중첩.)

### Frequency Governor
- AC-28: 4개 모드. 환경변수 FREQUENCY_MODE로 설정. TURBO: Stage1 3분/Stage2 30초/Kelly ×1.0. NORMAL: 5분/60초/×0.7. STEALTH: 10분/120초/×0.4.
- AC-29: AUTO 모드: DD <3% → TURBO, 3~6% → NORMAL, >6% → STEALTH.
- AC-30: 런타임 모드 변경 가능 (SIGHUP 시그널 또는 DB 플래그).

### Dual Executor
- AC-31: Sniper Executor: FOK 주문. slippage_tolerance 적용. CRITICAL/HIGH urgency.
- AC-32: Patient Executor: GTC + postOnly 주문. MEDIUM/LOW urgency.
- AC-33: DRY_RUN=true일 때 주문 미전송, 가상 체결 기록.

### Portfolio & DB
- AC-34: Portfolio Tracker: Data API 포지션 동기화 + DRY_RUN 가상 포지션 관리.
- AC-35: 일별 통계 (daily_stats) 자동 집계.

### 운영
- AC-36: Graceful shutdown (SIGINT/SIGTERM). 진행 중 주문 완료 대기 후 종료.
- AC-37: 구조화된 로깅 (logging 모듈). LOG_LEVEL 환경변수.
- AC-38: .env.example 제공. start.sh + start.bat 실행 스크립트.
