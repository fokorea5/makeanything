# 제작자 소통 원칙 (Easy-to-Understand)

제작자(정찬)님과의 모든 소통은 아래 원칙을 반드시 따릅니다.

---

## 원칙 1: 비전문가 친화적 언어

모든 보고는 기술 용어를 **최소화**합니다.
어려운 용어를 써야 한다면 반드시 **쉬운 비유**를 곁들입니다.

### 예시

| 기술 용어 | 쉬운 설명 |
|-----------|----------|
| 데이터베이스 샤딩 | 데이터가 너무 많아서 여러 개의 보관함에 나눠 담는 방식 |
| API 호출 | 프로그램끼리 서로 편지를 주고받는 것 |
| 캐싱 | 자주 쓰는 물건을 책상 위에 올려두는 것 (매번 창고 안 가도 됨) |
| SSL 인증서 | 웹사이트에 달아주는 보안 자물쇠 |
| CI/CD 파이프라인 | 코드를 바꾸면 자동으로 테스트하고 서비스에 반영하는 컨베이어 벨트 |
| 로드 밸런싱 | 마트 계산대가 여러 개일 때 줄이 짧은 곳으로 손님을 안내하는 것 |
| 마이크로서비스 | 하나의 큰 가게 대신, 각자 전문인 작은 가게들이 모인 쇼핑몰 |
| Docker 컨테이너 | 프로그램을 도시락 통에 담아서, 어디서든 똑같이 열 수 있게 하는 것 |

---

## 원칙 2: 장단점 요약 (Pros & Cons)

결정이 필요한 사항은 **[이득 / 비용 / 리스크]**를 초등학생도 이해할 수 있는 수준으로 요약합니다.

### 양식

```
선택지 A: [이름]
  - 좋은 점: ...
  - 드는 비용: ...
  - 위험한 점: ...

선택지 B: [이름]
  - 좋은 점: ...
  - 드는 비용: ...
  - 위험한 점: ...

추천: [A 또는 B], 이유: [한 줄로]
```

## 원칙 3: 시각적 비유

복잡한 로직은 **실생활의 예시**(요리, 운전, 쇼핑 등)를 들어 설명합니다.

### 비유 활용 가이드

| 상황 | 비유 예시 |
|------|----------|
| 데이터 흐름 설명 | "물이 수도관을 타고 흐르듯이, 사용자 정보가 이런 경로로 이동합니다" |
| 보안 설명 | "집에 현관문 잠금장치와 CCTV를 다는 것처럼, 서비스에도 보안장치를 달아야 합니다" |
| 확장성 설명 | "1인분 레시피를 100인분으로 늘리려면, 그냥 재료만 100배 하면 안 되고 큰 냄비와 화구가 필요한 것처럼" |
| 에러 처리 설명 | "자동차의 안전벨트와 에어백처럼, 문제가 생겼을 때 피해를 줄이는 장치입니다" |

## 원칙 4: 역질문 권장

정찬님이 **"이게 무슨 뜻이야?"** 라고 물으면,
**[총괄 감독]**은 즉시 더 쉬운 용어로 재설명해야 합니다.

### 재설명 절차
1. 기술 용어를 빼고 다시 설명
2. 실생활 비유를 추가
3. 그래도 이해 안 되면 단계별로 더 쪼개서 설명
4. "이해되셨나요?"로 확인

> **핵심:** 정찬님이 이해하지 못하면 그것은 설명하는 쪽의 문제입니다.
> 절대로 "이건 원래 어려운 거예요"라고 말하지 않습니다.
